# Weather Routing / xWeatherRouting 1.19.1 upstream handoff

## Merge and catalogue order

This branch reconciles Rick's master `b69925b` with the released source
`0df6c52ac73029dcee7e6bd8d0ca035dce45baf2`. Runtime code, regression tests,
data, dependency pin and production build recipes match that tested release.
The conflicts are resolved here; do not repeat a merge from the divergent
release branch. Rick's standalone manual build scripts and integration notes
are retained, but the recipes below are the ones qualified for this release.

The source supports both WeatherRouting and the separately installable
xWeatherRouting identity. The published packages and the linked acceptance
results are **xWeatherRouting**. CircleCI defaults to that identity; direct
CMake builds must set `WEATHER_ROUTING_XWEATHER_IDENTITY=ON` to reproduce it.
These catalogue entries do not replace the legacy WeatherRouting entries.

1. Review and merge the source PR into `rgleason/weather_routing_pi:master`.
2. Review the separate catalogue PR for `rgleason/plugins:Alpha`: Android
   arm64 and native Windows x64 only.
3. Review the separate catalogue PR for `rgleason/plugins:master`: Debian
   12/13 x86_64, Debian 12 arm64, Ubuntu 22.04/24.04 x86_64, Flatpak 25.08
   x86_64/aarch64, macOS arm64 and Windows x86.
4. Forward those catalogue changes to the same branches in `OpenCPN/plugins`.
   Merging Rick's fork alone does not update the official catalogue.

All eleven archives already exist at checksum-verified public URLs. The
catalogue PRs add SHA-256 checksums and use those existing URLs; rebuilding is
not necessary to publish this exact release. The Cloudsmith repository's
`alpha-oss` name describes storage, while the catalogue branch controls which
users see an entry. Do not rewrite a URL to a production repository unless
the archive has actually been uploaded there and independently verified.
Each archive already contains root `metadata.xml` for import. Submit only
the metadata changes and necessary schema update; let the catalogue's merge
workflow regenerate `ocpn-plugins.xml`.

## Rebuild the complete suite

Use a fresh clone of the merged source and initialize the pinned dependencies:

```sh
git clone --recurse-submodules https://github.com/rgleason/weather_routing_pi.git
cd weather_routing_pi
git submodule update --init --recursive
```

CircleCI now defaults `run_workflow_deploy=false` and
`build_xweather_identity=true`. A normal validation pipeline schedules all
22 builds: eleven platforms with API 1.21 headers, and the same eleven with
API 1.22 headers. Minimum advertised plugin API remains **1.21**. API 1.22
artifacts are compatibility evidence, not additional catalogue entries.

The tested build recipes replace the conflicting CircleCI/build-module
changes in Rick's current master, including the unresolved
`macos-universal`/`macos-arm64` dependency. Do not paste the older configuration
back over this one. Normal validation does not request deployment credentials.
The retained `deploy_reviewed_alpha` and recovery workflows belong to Paul's
existing personal-alpha publication process and still refer to his
`xgrib-deployment` context and `pob220/xweather-routing-alpha-oss` destination;
leave them disabled in Rick's project. Use the catalogue PRs for this release.

The opencpn-libs pin is
`b4e4aa267de99f4310beea18e2fa58e26a5bbcb8`. Its utility libraries are built
from source for the selected architecture. Missing prebuilt `tess2.lib` or
`bzip2.lib` is not a reason to remove those CMake targets. Keep the `ocpn::`
targets and the library lists as supplied.

## Manual Windows recipes

Use separate disposable checkouts for x86 and x64. Requirements: Visual
Studio 2022 Community with C++, Git, CMake, Python 3.11+, 7-Zip and Chocolatey.
The scripts install their pinned gettext dependency; Chocolatey requires
the usual installation permissions. Do not run them inside a working user
OpenCPN profile.

For native Windows x64, in a Windows command prompt at the checkout root:

```bat
set WEATHER_ROUTING_CI_XWEATHER=true
set WEATHER_ROUTING_API_HEADER_VERSION=1.21
call ci\circleci-build-windows64.bat
```

The target is `msvc-64;10;x86_64`. The script downloads the checksum-pinned
upstream OpenCPN 5.14.2 **testing** host and wxWidgets 3.2.9, extracts the host,
generates AMD64 `opencpn.lib` and `z.lib` from its actual exports, builds the
utility libraries, runs the regression suite, packages the plugin and runs
a short real-host route in an isolated portable profile. This is not the
older `msvc-wx32-x64` Preview target, and the stable 5.14.2 GitHub Windows
installer is x86. SDK URLs and hashes: [windows64-sdk.json](../ci/windows64-sdk.json).

For Windows x86:

```bat
set WEATHER_ROUTING_CI_XWEATHER=true
set WEATHER_ROUTING_API_HEADER_VERSION=1.21
set MSVC_VERSION=2022
set WX_VER=32
set OCPN_TARGET=MSVC
call ci\circleci-build-msvc.bat
```

For either architecture repeat in a separate clean checkout with
`WEATHER_ROUTING_API_HEADER_VERSION=1.22` for the header compatibility check.
Do not copy x86 import libraries into the x64 SDK. Keep
`_DISABLE_CONSTEXPR_MUTEX_CONSTRUCTOR`: the supplied Win32 host's old MSVC
runtime otherwise crashes with recent headers despite passing executor tests.

## Acceptance evidence and limitations

- [Final full workflow](https://app.circleci.com/workflow/7cbdee42-3121-4d2e-99ce-833ae8c134a6):
  all 22 builds passed. Twelve Linux/macOS suites passed 328 tests each;
  four Windows suites passed 331 each. Android and Flatpak are qualified
  by compilation/package checks; those jobs do not retain CTest suites.
- Both Windows architectures and both header variants completed actual
  upstream OpenCPN 5.14.2 host routes, including packaged polar/GRIB loading.
- The public Android library is byte-for-byte identical to the installed
  tablet-tested library. The real-GRIB Nicholson 35 Holyhead–Foyle route
  completed at 160.8 NM / 27 h 1 min and displayed on the chart. Cold startup
  loaded 1.19.1 successfully. Personal profiles/polars/screenshots stay local.
- All 22 public objects were fully downloaded and their deployment hashes
  verified. All eleven library architectures and embedded metadata were checked.
- The polar extrapolation fix `f0a2546` is included. Runtime source is retained
  exactly; this PR changes the default CI publication setting and adds handoff
  material, not new numerical behavior.
- macOS is **arm64**, despite the historical `macos-universal` job name.
  No Intel macOS or Android armhf package is supplied in this release.
- Android needs the patched tester host until the upstream import fix is
  available: [OpenCPN PR #5457](https://github.com/OpenCPN/OpenCPN/pull/5457),
  [full tester APK and instructions](https://github.com/pob220/OpenCPN-weather-routing/releases/tag/v5.14.1-pob220-import-fix).
