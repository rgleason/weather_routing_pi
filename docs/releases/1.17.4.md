# Weather Routing / xWeatherRouting 1.17.4

This development release fixes a shared routing search defect found while
investigating Windows report rgleason/weather_routing_pi#663. Validation targets
64-bit Linux; the Win32 support policy is unchanged.

* **Preserve complete connections at the search limit.** Before expanding the
  next isochrone layer, inspect the retained states for destination connections.
  Previously, a later incomplete state could exhaust the generated-state budget
  and discard an already found connection. The same bounded alternatives go
  through independent forward validation. Search budgets and safety checks
  are unchanged.
* **Identify the running build in the log.** Startup now records the plugin
  version, compiled API target and process bitness. This distinguishes reports
  from earlier binaries and does not imply a particular host application version.
* **Correct Windows address-space reporting.** Use the process limit reported
  by Windows instead of a fixed 2 GiB denominator, and include reserved as well
  as committed address space. Failed measurements display unavailable. Allocation
  failures record process address-space and commit headroom alongside free RAM;
  these measurements do not by themselves establish a leak or identify an owner.

## Validation

233 tests passed on native 64-bit Linux and Debian 12. The new bounded-search
regression fails against the original engine at 1,000 generated states and passes
with the fix, including independent route validation. Both plugin identities
build on Linux. A final headless Debian smoke test loads version 1.17.4.0
in a 64-bit host and completes a covered 10.455 NM synthetic GRIB route, including
244 independent validation samples; the process exits normally.

A controlled headless run using Rick's endpoint coordinates, the bundled
four-polar example boat and a synthetic forecast reaches the same bounded search
failure before and after this fix: 3,174,789 generated states and a 10.712 NM
closest approach. Both runs stay below 700 MiB sampled resident memory inside a
2 GiB container, with no memory-limit or OOM events. This longer-route search
limitation remains; the completion-ordering regression is a separate proven fix.
The comparison changes only the plugin binary in an isolated Debian runtime.

The Windows measurement helper cross-compiles for Win32. Wine confirms the
2 GiB versus 4 GiB host limits, but its approximate available-memory implementation
cannot validate reserved-only allocations. Native Windows validation of the
monitor remains outstanding and is separate from Linux release validation.

This release does not establish a fix for every reported rendering or routing
problem. Rick's exact tested plugin revision and original GRIB/configuration
remain unconfirmed; a synthetic forecast is not a reproduction of his weather.
