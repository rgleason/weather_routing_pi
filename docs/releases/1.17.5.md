# Weather Routing / xWeatherRouting 1.17.5

This release clarifies chart-depth requirements, exposes progress for ordinary
computations, and improves bounded recovery around continental obstructions.

* Positive minimum depth now names missing safety controls and distinguishes an
  unsupported host, unavailable chart-depth coverage, and a shallow endpoint.
  The controls explain that zero disables the numerical depth threshold, not
  land detection. All existing enforcement requirements remain in force.
* Headless results preserve preflight failures and their actionable reasons.
  Failed or unfinished calculations no longer export provisional geometry,
  arrival times or distances as result routes. Direct one-leg completions report
  their distance correctly. Existing process exit-code conventions are retained.
* Ordinary Compute and Compute All show modeless progress with route identities,
  effort, search stages, state/check counters, elapsed time and last worker update
  age. Hide keeps work running; View > Routing progress reopens it; Stop all
  computations explicitly cancels it. Readers retain each job's latest snapshot,
  and generation tokens reject callbacks from older jobs. Preparation counts are
  hidden during search because they are not a completion percentage.
* GPX export sanitizes filesystem separators and reserved punctuation in the
  filename while preserving the original route and position names in the GPX.
  This fixes export failures for names such as “3h / 10deg”.
* Long land-aware routes can retry the original forward cadence in a wider
  corridor after the narrow search collapses or repeatedly stagnates against
  land. This uses the existing search budgets and retains all motion constraints,
  currents, weather fallback and independent safety validation. No-land searches
  keep their original behavior. This does not guarantee every route completes.

## Validation

All 238 automated tests pass on native Linux and Debian 12, including the new
continental-detour and concurrent progress-mailbox regressions. Both plugin
identities build. A disposable GUI verifies single and concurrent computations,
Hide/reopen, worker cancellation and progress without a misleading percentage.

With the Nicholson 35 polar, the existing 15-day ECMWF forecast, offline tidal /
seasonal currents and Climatology wind fallback, continuous Provincetown–Lizard
routes complete with land detection at 100% effort: 3h/10° yields 2,809 NM and
6h/20° yields 2,826 NM. Their measured process peaks are approximately 1.49 and
1.41 GiB respectively. These are test routings, not navigation recommendations.

The CM93 Vava’u control preserves its 1.17.4 geometry exactly; a landward
endpoint is rejected. A positive 10 m depth control completes; excessive depth,
missing coverage, missing enforcement and an unsupported stock core produce
explicit failures. Quinton’s actual route and all chart providers are not
represented by these controls. Further regression measurements are recorded
in the accompanying development test report.
Quinton's exact saved island case has not been supplied; the local CM93 controls
are regression coverage, not a claim to have reproduced his exact test.

The 0.5-degree forecast also completes at 6h/20° (2,824 NM). Its 3h/10°
configuration still reaches the 100% state ceiling; coarser forecast resolution
alone does not guarantee a cheaper search. Selecting 200% on the successful
0.25-degree 3h/10° case preserves the same route and completes at the 100% tier.
These measurements used concurrent isolated tests, so elapsed times are not
controlled performance benchmarks. Higher effort remains available for harder
cases; default resource ceilings have not been increased.
